# Linkage Message

Веб-мессенджер: вход по имени пользователя и паролю (без телефона и почты), профиль с аватаром из галереи и датой рождения, поиск и добавление контактов по юзернейму, личные чаты и группы/каналы в реальном времени с индикатором «печатает…», эмодзи, реакции на сообщения, редактирование и удаление сообщений, вложения (фото/видео/файлы/голосовые), истории (Stories), персональные алиасы контактов, системные чаты «Избранное» и «Linkage Notifications», настройки профиля/приватности/уведомлений/сессий, смена пароля и удаление аккаунта.

Стек: HTML/CSS/JS (без сборки) + Firebase (Email/Password Auth «под капотом» + Firestore) + Cloudinary (хранение фото/видео/файлов чатов), деплой — статический хостинг на Vercel.

Полностью бесплатно: Firebase на тарифе **Spark**, Cloudinary на бесплатном тарифе — оба без привязки карты.

## 1. Настройка Firebase

1. https://console.firebase.google.com → создать проект.
2. **Build → Authentication → Get started → Sign-in method** → включите провайдер **Email/Password** (только первый переключатель; см. ниже, почему он нужен, хотя пользователи вводят только имя пользователя).
3. **Build → Firestore Database → Create database** (режим Production, любой регион).
4. Вкладка **Rules** в Firestore → вставьте содержимое [`firestore.rules`](./firestore.rules) → **Publish**.
5. **Project settings → General → Your apps** → `</>` Web → зарегистрируйте приложение (Hosting не подключать) → скопируйте `firebaseConfig` в [`public/firebase-config.js`](./public/firebase-config.js).
6. **Authentication → Settings → Authorized domains** → добавьте домен, на котором будет открываться сайт (например `<project>.vercel.app`); `localhost` там уже есть по умолчанию.

Карту привязывать не нужно, тариф Spark остаётся бесплатным.

### Как работает вход по имени пользователя без почты/SMS

Firebase Authentication из коробки не умеет «просто логин+пароль» — провайдер Email/Password требует что-то похожее на email. Поэтому при регистрации клиент сам генерирует случайный бессмысленный адрес вида `a1b2c3...@users.linkagemessage.app` и создаёт аккаунт на него — пользователь его никогда не видит и не вводит. Юзернейм и этот адрес связаны через документ `usernames/{username}` в Firestore. При входе клиент сначала находит по юзернейму этот адрес, а затем уже логинится им через Firebase Auth. Смена юзернейма в настройках просто переносит эту связь на новый документ — сам Firebase-аккаунт не трогается, поэтому пароль и вход продолжают работать.

### Роль «danik»

В [`firestore.rules`](./firestore.rules) юзернейм `danik` захардкожен как единственный аккаунт, которому разрешено писать в общий канал «Linkage Notifications» (коллекция `broadcasts`, читают все, пишет только он). Чтобы использовать эту возможность, зарегистрируйте аккаунт именно с юзернеймом `danik`.

### Составной индекс Firestore

Список чатов сортируется по времени последнего сообщения (`orderBy lastMessageAt`) при фильтре по участнику (`array-contains`) — Firestore для такого запроса требует составной индекс. При первом открытии списка чатов в консоли браузера появится ошибка со ссылкой вида `https://console.firebase.google.com/.../firestore/indexes?create_composite=...` — просто перейдите по ней и нажмите «Create index» (создастся за 1-2 минуты, потом ошибка исчезнет сама).

## 2. Настройка Cloudinary (хранение фото/видео/файлов в чатах)

Firestore хранит только текст и метаданные сообщений — сами фото, видео, файлы и голосовые загружаются напрямую из браузера в Cloudinary (без бэкенда), а в Firestore попадает только ссылка на файл.

1. https://cloudinary.com/users/register/free → зарегистрируйтесь (бесплатный тариф, без карты).
2. На Dashboard скопируйте **Cloud name** (например `dxxxxxx`).
3. **Settings (шестерёнка) → Upload → Upload presets → Add upload preset**:
   - **Signing Mode: Unsigned** (обязательно — иначе загрузка с клиента без бэкенда невозможна).
   - Сохраните и скопируйте имя пресета (**Upload preset name**).
4. Впишите оба значения в [`public/cloudinary-config.js`](./public/cloudinary-config.js):
   ```js
   export const CLOUDINARY_CLOUD_NAME = "dxxxxxx";
   export const CLOUDINARY_UPLOAD_PRESET = "ваш_preset";
   ```

Оба значения публичные по своей природе (unsigned-загрузка так и задумана Cloudinary) — секретный API-ключ нигде в клиентском коде не нужен и не используется. Пока файл не заполнен реальными значениями, кнопка-скрепка и голосовые сообщения будут показывать ошибку «Загрузка файлов не настроена».

## 3. Локальная проверка

```bash
npx serve public
# или
python3 -m http.server 8000 --directory public
```

## 4. Деплой на Vercel

1. Запушьте репозиторий в GitHub.
2. https://vercel.com → **New Project → Import Git Repository**.
3. Output Directory уже прописан в `vercel.json` как `public`, Framework Preset — "Other".
4. **Deploy**.
5. Не забудьте добавить `<project>.vercel.app` в Authorized domains (шаг 6 выше), иначе вход будет падать с ошибкой домена.

## Как это работает

**Вход и регистрация — отдельная страница `/login`:**
- Одна форма. По умолчанию режим «Вход» (юзернейм + пароль). Внизу ссылка «Ещё нет аккаунта? Зарегистрируйтесь» переключает форму в режим регистрации (и обратно такой же ссылкой снизу).
- В режиме регистрации дополнительно показываются: аватар (фото из галереи, необязательно), ник (отображаемое имя), поле «Подтвердите пароль». У полей пароля есть иконка-глазик для показа/скрытия введённого текста.
- После успешного входа/регистрации — редирект на `/` (сам мессенджер).

**На главной странице нет вкладок** — сразу единый список чатов. Сверху всегда закреплены:
- **Избранное** — заметки самому себе (`users/{uid}/savedMessages`), видны только вам.
- **Linkage Notifications** — системный канал: сюда автоматически падают уведомления о входах в ваш аккаунт (`users/{uid}/systemChat`, видно только вам), а также общие объявления, которые может отправлять всем пользователь `danik` (`broadcasts`, видно всем).

Новый чат — кнопка с карандашом внизу справа открывает окно с тремя вариантами: «Новый контакт» (поиск по юзернейму), «Новая группа», «Новый канал». Поиск в самом сайдбаре тоже работает и ведёт к тому же результату для контактов.

**Контакты:**
- Найденного пользователя можно добавить в контакты и/или сразу написать.
- Каждому контакту можно задать свои имя и фамилию (иконка карандаша в шапке открытого чата) — они показываются в списке чатов и в заголовке вместо ника пользователя, как в Telegram.

**Чаты:**
- Личные (1:1) — коллекция `chats/{chatId}/messages`, ID чата — детерминированная комбинация двух uid.
- Список чатов и сообщения обновляются в реальном времени через `onSnapshot`.
- Индикатор «печатает…» (только в личных чатах): при вводе текста клиент проставляет метку времени в `chats/{chatId}.typing.{uid}`, собеседник видит «печатает…» вместо статуса, если метка свежее ~6 секунд; метка снимается по таймеру простоя или сразу при отправке сообщения.

**Группы и каналы (`groups/{groupId}`):**
- Создаются через кнопку-карандаш: название, необязательное фото, участники добавляются поиском по юзернейму (создатель — владелец и единственный админ на момент создания).
- *Группа* — писать может любой участник; *канал* — писать может только админ (пока это создатель), остальные участники только читают.
- В группах над входящими сообщениями показывается имя отправителя (у каналов и личных чатов — нет, там и так понятно кто пишет).
- И группы, и обычные чаты показываются в одном списке, отсортированном по времени последнего сообщения.

**Сообщения — вложения, эмодзи, реакции, редактирование:**
- Кнопка со смайликом открывает сетку эмодзи, вставляет символ в поле ввода.
- Кнопка-скрепка позволяет прикрепить фото, видео, файл или GIF (обычный `<input type="file">`, без поиска гифок по API — просто загрузка файла с диска/из галереи). Фото и видео показываются превью прямо в чате, файлы — карточкой с именем и размером.
- Кнопка-микрофон записывает голосовое сообщение (`MediaRecorder`), после записи можно прослушать и отправить или удалить.
- Все вложения (фото/видео/файлы/голосовые) загружаются напрямую в Cloudinary (см. раздел про настройку выше), в Firestore попадает только ссылка на файл — лимит на размер отдельного файла ~25 МБ (клиентская проверка перед загрузкой), а не ~700 КБ, как было бы при хранении base64 в Firestore. Требует заполненного `public/cloudinary-config.js` — иначе вложения отправлять нельзя.
- Долгое нажатие/наведение на своё сообщение показывает реакции (эмодзи-пилюли) и, только для своих сообщений, кнопки «Редактировать»/«Удалить». Реакции может ставить любой участник чата/группы.
- Клик по трём точкам в шапке чата открывает меню «Очистить историю» (только у себя, сообщения остаются у собеседника) и «Удалить чат» (тоже только для себя — чат снова появится, если придёт новое сообщение).

**Истории (`stories/{id}`):**
- Фото-истории живут 24 часа, видны всем зарегистрированным пользователям (не только контактам — полноценной модели «подписчиков» пока нет).
- Добавляются через ленту сторис вверху списка чатов (свой аватар с «+»). Автор может удалить свою историю досрочно.
- Просмотр — полноэкранный оверлей с прогресс-баром, автоматически листает дальше, свайп/кнопки для навигации между историями разных пользователей.

**Настройки (клик по аватару в сайдбаре открывает список разделов; конкретный раздел открывается только по клику на него, с кнопкой «назад»):**
- *Профиль* — фото из галереи, ник, юзернейм (смена через транзакцию), статус/о себе, дата рождения.
- *Приватность* — кто видит время последнего захода.
- *Уведомления* — звук, системные уведомления браузера (Notification API, работают пока вкладка открыта — без push/service worker), превью текста.
- *Сессии* — кнопка «Выйти из аккаунта»; смена пароля (с подтверждением текущего пароля и показом/скрытием вводимого); история входов, где текущая сессия отдельно помечена «Текущая сессия» (остальные можно «забыть» из списка); удаление аккаунта (требует повторного ввода пароля; удаляет юзернейм и профиль, аккаунт Firebase Auth удаляется последним).

## Структура данных Firestore

- `users/{uid}` — профиль: `username`, `displayName`, `avatarColor`, `avatarImage` (data URL или `null`), `bio`, `birthday`, `privacy`, `notifications`, `lastSeenAt`
  - `users/{uid}/contacts/{contactUid}` — контакт: `addedAt`, `firstName`, `lastName` (алиас)
  - `users/{uid}/savedMessages/{id}` — «Избранное»: `text`, `createdAt`, `edited`, `editedAt`
  - `users/{uid}/systemChat/{id}` — личные уведомления: `text`, `createdAt`
  - `users/{uid}/sessions/{id}` — история входов: `device`, `createdAt`
- `usernames/{username}` → `{ uid, authEmail }` — индекс логина/уникальности (публично читаемый — нужен для входа до авторизации)
- `broadcasts/{id}` — объявления от `danik`, читают все: `text`, `senderId`, `createdAt`
- `stories/{id}` — `ownerId`, `image` (data URL), `createdAt` (клиент фильтрует по 24ч)
- `chats/{chatId}` — `participants`, `lastMessage`, `lastMessageAt`, `lastMessageSenderId`, `typing` (карта `uid -> timestamp`), `hiddenFor` (массив uid, «удалено у себя»), `clearedFor` (карта `uid -> timestamp`, «очищено у себя»)
  - `chats/{chatId}/messages/{id}` — `text`, `senderId`, `createdAt`, `edited`, `editedAt`, `reactions` (карта `emoji -> [uid]`), `imageUrl`/`fileUrl`/`voiceUrl` (ссылки на Cloudinary, опционально), `fileName`/`fileType`/`fileSize` (для `fileUrl`)
- `groups/{groupId}` — `type` (`group`/`channel`), `name`, `avatarColor`, `avatarImage`, `ownerId`, `admins`, `members`, `lastMessage`, `lastMessageAt`, `lastMessageSenderId`, `hiddenFor`, `clearedFor`
  - `groups/{groupId}/messages/{id}` — `text`, `senderId`, `createdAt`, `edited`, `editedAt`, `reactions`, вложения (как в чатах)

- `public/contacts.js` — поиск, список контактов, алиасы (имя/фамилия контакта)

- `public/saved.js` — «Избранное»
- `public/notify.js` — «Linkage Notifications» (личные уведомления + объявления `danik`)
- `public/groups.js` — группы и каналы
- `public/stories.js` — истории (создание/удаление/лента за 24ч)
- `public/settings.js` — обновление профиля/юзернейма/приватности/уведомлений

## Известные ограничения

- Вкладка «Сессии» показывает только историю входов (устройство + время). Удалённо «выкинуть» другое устройство нельзя — для этого нужен Admin SDK/бэкенд, которого в этом проекте нет.
- Настройка приватности «последний визит» проверяется на клиенте — это ограничивает UI, но не является полноценной серверной защитой.
- Статус «в сети» — эвристика по `lastSeenAt` (обновляется раз в ~45 сек и при возврате на вкладку), а не настоящий realtime presence.
- Уведомления браузера работают только пока вкладка/приложение открыты — не push-уведомления (для них нужен Firebase Cloud Messaging + Service Worker).
- Удаление аккаунта не подчищает старые чаты/сообщения/группы с другими пользователями (Firestore-правила не разрешают удалять чужие данные с клиента) — только профиль, юзернейм и сам аккаунт.
- В группах/каналах пока нет управления участниками после создания (добавить/удалить, назначить админа канала, покинуть группу) и нет счётчика непрочитанных — это следующий шаг.
- Аватары (профиля и групп) и картинки историй по-прежнему хранятся как base64 внутри документов Firestore (это небольшие сжатые изображения, ~20-60 КБ, укладываются в лимит документа с большим запасом) — на Cloudinary переведены только вложения сообщений (фото/видео/файлы/голосовые), которые могут быть значительно больше.
- Firestore-правила больше не ограничивают размер вложений (это делает Cloudinary на своей стороне) — правила лишь проверяют, что в поле лежит строка-ссылка разумной длины, а не бинарные данные.
- GIF нельзя найти поиском — только загрузить файлом (через кнопку-скрепку), интеграции с Tenor/Giphy нет.
- Cloudinary настроен на unsigned upload preset — это означает, что кто угодно, кто знает cloud name и имя пресета (оба публичные, видны в исходниках сайта), теоретически может залить файл в ваш аккаунт Cloudinary напрямую (в обход самого мессенджера). Firestore это не затрагивает (ссылка попадёт в базу только если пройдут её собственные правила), но при разработке рекомендуется включить в настройках пресета Cloudinary ограничения по типам/размеру файлов и следить за использованием бесплатной квоты.
- Правила Firestore разрешают ставить/снимать реакцию любому участнику чата, но не проверяют, что человек меняет запись именно под своим uid внутри карты `reactions` — теоретически можно подделать чужую реакцию через прямой запрос к Firestore (не через UI). Не критично, но стоит иметь в виду.
- Истории видны всем зарегистрированным пользователям, а не только контактам/подписчикам — модели приватности для историй пока нет.
